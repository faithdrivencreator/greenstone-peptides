## Gotchas to remember

1. **Bloom URL doubled-path bug** — `NEXT_PUBLIC_PHARMACY_URL` must be the bare host. If a future operator pastes the full storefront URL into the env, the now-defensive helper will recognize the `/dtp/` and use the env value as-is. See `src/lib/pharmacy.ts` and memory `reference_bloom-pharmacy-url-helper.md`.
2. **Bloom storefront layout setting** — must be **Lightweight** in Bloom dashboard (`https://bloom.greenstonerx.com/store`). Educational mode breaks our "single Continue to Pharmacy click → catalog" flow.
3. **Netlify redirect audit blind spot** — source-only grep audits will miss redirects defined in `netlify.toml`. Always read `netlify.toml` when chasing 404s on URLs that look correct in source.
4. **Bloom admin cookie contamination** — once Pete signs into the Bloom admin dashboard in a browser, that browser's Bloom session cookie will cause subsequent visits to `/dtp/<id>` to re-route to the provider portal. iCloud Keychain can sync this across Mac browsers. Don't QA the customer funnel in a browser that's been used for Bloom admin. (This was a false-trail diagnosis earlier in the session — the real fix was the doubled-path bug, but the cookie issue is still a real annoyance for Pete's own testing.)
5. **Maintenance bypass cookie** — `gs_bypass=ok`, set by `POST /api/maintenance-bypass` with correct password. 7-day expiry. To re-lock your own browser, clear cookies for greenstonewellness.store or call `DELETE /api/maintenance-bypass`.
